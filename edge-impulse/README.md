# Edge Impulse / TinyML Integration

This folder documents the Edge Impulse experimentation path used for the Kitchen/Living Room environmental classifier.

The public project is intentionally structured so that the deterministic safety logic remains fully inspectable and runnable without a generated Edge Impulse library:

```cpp
#define USE_EDGE_IMPULSE_RUNTIME 0
```

## Why the generated inferencing ZIP is not committed

Edge Impulse deployment archives can include generated runtime/SDK components and other third-party material under licence terms that are separate from this repository's MIT-licensed original code.

For that reason, the hardened public source tree documents how to regenerate the deployment package instead of redistributing a generated binary/source archive whose complete third-party licensing depends on the export configuration and account/project terms.

The training/test screenshots under `assets/` remain as evidence of the experiment.

## Reproducing the deployment path

1. Create or clone an Edge Impulse project.
2. Import equivalent simulated sensor data.
3. Train and test the environmental classifier.
4. Export an Arduino/C++ inferencing library under the licence terms applicable to your Edge Impulse project.
5. Add that library to the Arduino/Wokwi environment.
6. In `wokwi/kitchen-living-room/sketch.ino`, replace the current project-specific inferencing `#include` with the header generated by your own export.
7. Set:

   ```cpp
   #define USE_EDGE_IMPULSE_RUNTIME 1
   ```

8. Compile and validate the runtime on the intended target.

## Interpretation of the model results

The training dataset is **simulated and rule-labelled**. The classifier therefore learns decision regions that were deliberately generated from the same input variables. Strong test performance is expected and demonstrates the embedded-ML workflow; it is not independent evidence that the model can detect real household hazards.

The rule-based safety path remains the default behaviour in the public Wokwi demo. Real-world use would require calibrated sensors, independently labelled data, hardware testing and a safety review.
